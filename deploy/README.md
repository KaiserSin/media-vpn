# Архив развёртывания Media primary + CDN

Это параметризованные скрипты существующей установки Media, подготовленные 23 октября 2026 года из исходников развёртывания от 8 сентября. Они сохраняют прежние форматы Xray, порядок primary/CDN, пути служб, резервные копии и проверки. Этот каталог не является универсальным установщиком. Скрипты выполняют изменения сразу при явном запуске; импортировать их как библиотеку или запускать все подряд нельзя. При подготовке архива они не запускались.

## Зависимости

- Сервер Linux amd64 с systemd, nginx, Python 3.9+, модулем `venv`, `pip`, системными командами `useradd`, `id`, `nginx`, `systemctl` и группой `www-data`. Для серверных скриптов нужны права записи в `/etc`, `/opt`, `/var/lib` и управления службами.
- Xray-core **26.7.28** в `/opt/happ-vpn/v26.7.28/xray`. `prepare-origin.py` скачивает Linux amd64 архив этой версии и проверяет закреплённый SHA256; бинарник в репозиторий не включён.
- `certbot==5.8.0` в `/opt/happ-vpn/certbot`. Подготовительный скрипт создаёт это окружение и устанавливает пакет из сети.
- Для локальных скриптов: Python 3.9+ без сторонних Python-пакетов, OpenSSH `ssh`, проверенный Xray-core 26.7.28 для локальной платформы, доступ к приватной подписке по HTTPS.
- Существующий HTTPS origin, действующий сертификат для выбранного IP в `/etc/happ-certbot/live/happ-origin/`, доступный HTTP ACME challenge и заранее настроенный CDN. Получение первого сертификата, создание CDN, DNS, firewall и их внешние настройки этими файлами полностью не воспроизводятся.

## Параметры окружения

Параметры должны задаваться оператором отдельно от репозитория. Live-state не хранится здесь.

| Переменная | Где нужна | Значение |
|---|---|---|
| `MEDIA_EXISTING_NGINX_SITE` | `server/prepare-origin.py` | Полный путь существующего HTTP сайта nginx. В нём должен быть ровно один якорь `    location / {`; скрипт добавляет ACME location и делает резервную копию. |
| `MEDIA_ORIGIN_IP` | `server/configure-origin.py`, `server/publish-happ.py`, `local/build-media-auto.py` | Настоящий публичный IP origin; он же IP SAN сертификата и TLS `serverName`. |
| `MEDIA_CDN_HOST` | `server/publish-happ.py` | Имя заранее настроенного CDN, без схемы и пути. |
| `MEDIA_SSH_HOST` | оба `local/*.py` | Адрес или SSH alias сервера. Доступ должен быть заранее настроен; интерактивного ввода пароля нет. |
| `MEDIA_WORK_DIR` | оба `local/*.py` | Приватный runtime-каталог вне репозитория. Подкаталог `xray-client/` должен существовать. |
| `MEDIA_XRAY` | `local/build-media-auto.py` | Полный путь локального Xray-core 26.7.28. |

Не подставляйте публичный IP в loopback назначения `127.0.0.1`: они связывают nginx с локальными Xray inbounds.

## Содержимое и условия запуска

| Файл | Что делает и какие данные требуются |
|---|---|
| `server/prepare-origin.py` | Делает резервную копию выбранного HTTP сайта, добавляет ACME location, загружает закреплённый Xray и устанавливает certbot. Требует работающий nginx и сетевой доступ к источникам пакетов. |
| `server/configure-origin.py` | Создаёт или читает `/etc/happ-vpn/setup-state.json`, формирует XHTTP origin и systemd службу, HTTPS сайт nginx и timer обновления сертификата. При повторном запуске читает ключ расшифрования из существующего `/etc/happ-vpn/server.json`. Сертификат должен уже существовать. Это базовый этап: его повторный запуск после последующих доработок заменяет server config базовым вариантом. |
| `server/update-media-path.py` | Историческая миграция XHTTP пути на `stream.txt` и идентификаторов сеанса/последовательности в query. Требует существующие state и server config; должна рассматриваться отдельно от генерации нового origin. |
| `server/add-media-primary.py` | Добавляет WSS/VLESS inbound на loopback:18083 и nginx location к существующему origin. Читает state и XHTTP inbound, валидирует Xray/nginx, перезапускает Xray и перечитывает nginx. |
| `server/publish-happ.py` | Создаёт приватный Xray клиент и опубликованную приватную подписку из live-state. Если `profile_mode` уже равен `automatic`, сохраняет primary/CDN и observatory. Адрес подписки формируется только на сервере из origin IP и приватного токена. |
| `local/build-media-auto.py` | По SSH читает live-state, загружает действующую подписку, создаёт `MEDIA_WORK_DIR/xray-client/media-auto-candidate.json`, проверяет его локальным Xray. Кандидат содержит доступ к VPN и должен храниться приватно. Ничего не публикует. |
| `local/deploy-media-auto.py` | Требует этот кандидат и отдельный актуальный `MEDIA_WORK_DIR/media-failover-result.json` с `passed: true`. Повторно проверяет candidate на сервере, делает резервные копии и публикует профиль. Наличие флага в старом JSON не доказывает текущую работу сети. |

Порядок выше объясняет историю настройки, а не предлагает автоматический прогон. Перед исполнением сравните live-state и действующие server/nginx configs с ожидаемыми входами каждого конкретного скрипта. Здесь нет оболочки, которая запускает цепочку, меняет подключение Happ или применяет серверные изменения при клонировании.

## Приватные данные и границы проверки

`setup-state.json`, `server.json`, клиентские профили, резервные копии и опубликованный `happ.json` содержат действующие параметры доступа. Они создаются/читаются только во внешних runtime-каталогах и не должны попадать в Git. Ссылки подписок, токены, UUID, ключи, HTTP cookies и реальные адреса установки в архив не включены.

В исходной схеме primary — WSS непосредственно к origin, резерв — VLESS/XHTTP через CDN. Это отдельный путь от Media Test 10 с Яндекс Документами. Проверка синтаксиса и Xray `-test` подтверждают структуру конфигурации; фактическое соединение, переключение и доступность при белых списках требуют отдельных сетевых проверок.
