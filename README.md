# Media VPN через Яндекс Документы

Исходники Media/OpenFlux для Happ, восстановленные и проверенные 23 октября 2026 года. Профиль **Media Test 10 MUX** направляет VLESS через локальный SOCKS-адаптер, десять каналов совместного редактирования Яндекс Документов и собственный VPN-сервер.

## Подключение нового Mac

Начни с [пошаговой инструкции для нового Mac](docs/macos-setup.md): где получить приватный пакет, как установить адаптер, добавить исключения и импортировать профиль в Happ. Готовый приватный архив передаёт владелец VPN; в GitHub его нет.

## Проверенное состояние

Короткий тест **в системном VPN Happ** прошёл: HTTPS вышел через собственный VPS в NL с TLS 1.3; получен HTTP 200 и файл **1 048 576 байт за 23,028 с**. После теста Happ отключён, обычный интернет проверен отдельно. На обеих сторонах после проверки доступны 10/10 каналов.

Изолированные нагрузочные проверки варианта MUX прошли шестью сериями по 96 HTTPS-запросов. До включения MUX системный профиль не работал под нагрузкой, хотя отдельная передача файла удавалась.

Это проверка короткой передачи, с невысокой скоростью. Длительная стабильность, работа в конкретной сети оператора с белыми списками, UDP, IPv6 и мобильный клиент **не проверены**. Подписанные настройки документов могут потребовать ручного обновления. Подробности и прежние сбои — в [отчёте](docs/status-2026-10-23.md).

## Что исправлено

- Добавлен явный приватный `--doc-bootstrap-file`: старые анонимные ссылки Диска больше не возвращали конфигурацию редактора.
- Cursor-пакеты объявляют фактическую длину данных; stream-блок уменьшен до 1024 байт по измерениям текущего сервиса.
- Необязательный `dialAddress` и проверенная версия редактора устраняют DNS/API-зависимость переподключения. Host, SNI и проверка TLS сохраняются.
- MUX основного outbound объединяет запросы в меньшее число внешних потоков relay. Параметры проверенного варианта: `enabled: true`, `concurrency: 128`.
- На Mac точный IP сервера редактора исключён из системного VPN, чтобы транспорт не попадал внутрь собственного туннеля.

Формат приватного bootstrap, ограничения и обновление описаны в [инструкции](docs/yandex-bootstrap.md). Документы, токены, ключи relay, действующие профили и подписки в репозиторий не включены.

## Содержимое

- `openflux/` — исходник локальной ветки с описанными исправлениями и безопасной диагностикой разрывов. [Происхождение и проверки](openflux/UPSTREAM.md).
- `templates/` — шаблоны Xray, Happ, nginx и служб с заполнителями.
- `client/macos/` — установщик локального адаптера для Apple Silicon.
- `diagnostics/check_profile.py` — проверка личного профиля через отдельный локальный SOCKS, без переключения Happ.
- `deploy/` — параметризованный архив исходной настройки Xray/nginx и обычного профиля Media. Успех обычного Media не подтверждает транспорт Яндекс Документов.

Это исходники существующего развёртывания. На новом сервере нужны Xray, nginx, доверенный TLS-сертификат, пользователи служб и собственные согласованные конфигурации. Следуйте README соответствующего каталога; шаблоны с `<...>` и `example.com` нельзя запускать без заполнения. Один импорт JSON в мобильный Happ не создаёт локальный адаптер.

## Сборка OpenFlux

Требуется Go 1.26.4 или совместимый Go, способный собрать исходный `go.mod`.

```sh
cd openflux
go test -mod=readonly ./...
go test -mod=readonly -race -short ./...
CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 go build -o ../bin/media-adapter-msr .
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o ../bin/media-openflux-stream .
```

Полный набор тестов, детектор гонок и обе сборки прошли для исправления bootstrap/dialAddress. Последующее добавление диагностики разрывов прошло тесты и race-проверку затронутого пакета и обе сборки. Unit-тесты используют локальные заглушки; результаты живой передачи приведены отдельно в отчёте.

## Проверка личного профиля

Нужны Python 3, curl, Xray и существующий **личный** JSON-профиль вне репозитория. Для варианта через документы локальный адаптер уже должен работать.

```sh
python3 diagnostics/check_profile.py --profile /path/to/private/profile.json --xray /path/to/xray --timeout 45
```

Проверка скачивает 1 МиБ, выводит результат JSON и завершает только созданный ею Xray. Она сохраняет маршрутизацию профиля, не меняет Happ и системные маршруты. При массиве профилей используется первый. Необязательный `--outbound primary` или `--outbound cdn` принудительно выбирает соответствующий outbound; это отдельная проверка, не подтверждение Яндекс-транспорта.
